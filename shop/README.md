# 自助下单网站

一个可以自己发布商品、买家自助下单的独立站。支持**卡密自动发货**和**人工发货**两种商品，
收款方式（微信/支付宝收款码）在后台随时可改，不依赖任何第三方支付平台。

- 后端：Node.js + Express + SQLite（用 Node 内置的 `node:sqlite`，**不需要单独装数据库**）
- 前端：原生 HTML / CSS / JavaScript，**没有构建步骤**，改完刷新即可

**环境要求：Node.js 24 或更高版本。**

> 这一条不能凑合。项目用 Node 内置的 SQLite 模块存数据，Node 22.5 以下根本没有这个模块，
> 22.x 用的还是不稳定 API，只有 24 才是稳定版。启动时会自动检查版本，不达标会给出升级提示。

## 快速开始

```bash
npm install
npm start
```

打开 http://localhost:3000 就是店铺首页，http://localhost:3000/admin 是管理后台。

**首次启动会自动创建管理员账号：**

| 账号 | 密码 |
| --- | --- |
| `admin` | `admin123` |

> ⚠️ 登录后请立刻到「账号安全」里改掉密码。

同时还会写入 3 个演示商品（2 个自动发货、1 个人工发货），可以直接删掉换成你自己的。

## 完整使用流程

### 1. 配置收款（必须先做）

进后台 →「收款设置」，上传你的微信 / 支付宝收款码：

- 微信收款码：微信 → 我 → 服务 → 收付款 → 二维码收款 → 保存收款码
- 支付宝收款码：支付宝 → 收钱 → 保存图片

没配置收款码之前，买家在付款页会看到「请联系客服付款」，不会显示任何收款信息。

### 2. 发布商品

后台 →「商品管理」→「发布新商品」，填名称、价格、封面、详情即可。

**发货方式选哪个：**

| 类型 | 适合 | 买家体验 |
| --- | --- | --- |
| **自动发货** | 卡密、激活码、兑换码、会员直充 | 你确认收款后系统立刻发卡密，秒到 |
| **人工发货** | 实物、需要人工处理的服务 | 买家填收货地址，你填快递单号 |

自动发货商品需要**预先导入卡密**。

### 3. 导入卡密（自动发货商品）

后台 →「卡密库存」→ 选商品 →「批量导入卡密」：

- 一行一条，一次最多 5000 条
- 自动跳过重复内容
- 需要同时发账号密码时，写成一行即可，例如 `user@example.com----pass1234`

商品列表里会显示每个商品的卡密余量，少于 5 条时后台首页会红色预警。

### 4. 日常接单

买家下单 → 扫码付款（**备注订单号**）→ 点「我已完成付款」→ 你收到通知。

你在「订单管理」里核对到账后：

1. 点 **确认收款**
   - 自动发货商品：卡密立刻发出，订单直接完成
   - 人工发货商品：订单进入「待发货」
2. 人工发货商品再点 **发货**，填快递单号

买家在订单页和「订单查询」里就能看到卡密或快递单号。

## 买家侧的完整流程

```
首页浏览商品 → 商品详情页填联系方式/收货信息 → 下单
    ↓
支付页：展示收款码 + 应付金额 + 订单号，30 分钟倒计时
    ↓
买家扫码付款（备注订单号）→ 点「我已完成付款」
    ↓
商家核对到账 → 确认收款 → 自动发卡密 / 人工发货
    ↓
买家在支付页或「订单查询」里取卡密 / 查快递单号
```

支付页每 10 秒自动刷新一次，商家一发货买家就能看到，不用手动刷新。

## 数据与备份

所有数据都在 **`data/shop.db`** 一个文件里（SQLite）。备份就是复制这个文件：

```bash
# 备份
cp data/shop.db ~/backup/shop-$(date +%F).db

# 恢复：停掉服务 → 覆盖文件 → 重新启动
```

上传的图片在 `public/uploads/`，备份时一起复制。

后台「系统设置」里还可以**导出订单为 CSV**（Excel 直接打开不乱码）。

### 清空重来

```bash
npm run reset               # 只清数据库
npm run reset -- --uploads  # 连上传的图片一起清
```

| 文件 | 用途 |
| --- | --- |
| `deploy/shop.service` | systemd 服务单元，实现开机自启 + 崩溃自动重启 |
| `deploy/nginx-shop.conf` | Nginx 反向代理配置（等你要绑域名、上 HTTPS 时再用） |

### 可用的环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | 监听端口 |
| `HOST` | `0.0.0.0` | 监听地址。挂在 Nginx 后面建议设成 `127.0.0.1` |
| `TRUST_PROXY` | 关 | 设成 `1` 时信任代理头。**用了 Nginx 就必须打开**，否则限流会把所有买家当成同一个 IP |

## 安全说明

已经做了的处理：

- 管理员密码用 **scrypt** 加盐散列存储，数据库泄露也无法反推明文
- 登录失败限流（同 IP 10 分钟内 8 次锁定）
- 会话写库 + HttpOnly Cookie，服务重启不掉登录；改密码会踢掉其他设备
- 所有 SQL 都是参数化查询，无拼接
- 页面渲染统一转义，商品详情走自研的安全 Markdown 渲染（先转义再替换），无 XSS
- 图片上传校验文件头（不信任 Content-Type），文件名随机生成，防目录穿越
- 配置了 CSP、`X-Frame-Options`、`nosniff` 等安全响应头
- 订单查询需要「订单号 + 下单时的联系方式」双重匹配，防止拿到订单号就偷卡密
- 下单接口限流，自动发货商品在事务内二次校验库存，防并发超卖

### 两个需要你注意的地方

1. **务必改掉默认密码** `admin123`，并且不要把 `/admin` 暴露给无关的人。

2. **「系统设置」里的「买家点我已付款后自动确认发货」默认是关闭的，建议一直保持关闭。**
   开启后买家点一下就自动发卡密，**不会核对是否真的到账**——任何人都能白拿商品。
   只有当你的收款方式能可靠地人工/自动核对到账时才可以考虑打开。

3. 本站**不接入第三方支付接口**（接入微信/支付宝官方接口需要企业商户资质）。
   收款流程是：买家扫码 → 备注订单号 → 你人工核对到账 → 后台点确认。
   如果需要全自动到账，可以对接易支付/码支付这类聚合支付，在 `src/service.js`
   的 `confirmPayment()` 处挂一个回调接口即可，收款配置的存储结构是通用的。

## 常见问题

**改了样式不生效？**
HTML 是 `no-cache`，但 CSS/JS 有 1 小时缓存，强制刷新（Ctrl+F5）一下。

**想换配色？**
改 `public/css/style.css` 顶部的 `:root` 变量即可，暗色模式在 `[data-theme='dark']` 里。

**商品删不掉？**
已经卖出过的商品不能真删（会破坏历史订单），系统会自动改成下架。

**订单一直显示待付款？**
买家没点「我已完成付款」，或者你还没在后台点「确认收款」。超过 30 分钟未付款会自动关单（可在系统设置里改）。

**卡密发不出去？**
卡密库存不足。到「卡密库存」补货，然后在该订单上点「发货」手动重试即可。
